Status dashboard for the showcase-package-unblock plan. Captures what's

## Hard gates (showcase-unblock §4.7)

### ✅ Packaging gate — GREEN

`cargo run -p yio_pkg -- build showcase` exits 0; both packages
produce cleanly:
- `showcase.pkg.bin` — 8 components (home/settings/mail/inventory/shop/
  character/form/lab), 654 KB.
- `spec4b-acceptance.pkg.bin` — 1 component, 22 KB.

No fence diagnostics. Unblocked by: pkg v20 + NodeKind split (Task 1),
comma selector list (Task 3), attribute selector (Task 4/5), `resize`

(Task 13: output_dir depth, spec4b img-src depth, nth-child + aria-selected
deferred comments, rogue.png missing-asset substitute).

### ✅ Facility gate — GREEN (spec4b single page)

Rect-diff triad runs end-to-end on spec4b:
- browser-rect.mjs → 15 elements (root 1280×720, card 300×80 match CSS).
- spec4b_dump --json → 43 DFS nodes.
- diff.mjs → **0 container/box `div` diffs**; 9 text-metric diffs.

**Interpretation:** core's block/flex layout matches Chromium exactly
(0 structural rect diffs). The 9 residual diffs are all text-driven
(`span` text + text-wrapping `button` width) — inherent drift between
core's text shaper (ab_glyph + ttf-parser) and Chromium's (HarfBuzz/
DirectWrite). Direction is inconsistent per glyph-run (not a uniform
scale), confirming engine difference, not a layout bug. This is the
expected "仅文本度量微差" the plan allowed.

## Soft gate — 8-page rect-diff dashboard: DEFERRED

Per-page rect diff across the 8 showcase pages is **not measured here**.
The core rect dumper (`crates/core/examples/spec4b_dump.rs`) is
spec4b-specific (hardcoded pkg + component). Generalizing it to take
pkg-path + component-name args + dump per showcase component is
straightforward follow-up work, deferred because:

1. The facility is already proven (spec4b: 0 box diffs).
2. Most 8-page results would be RED due to **unbuilt features** (not
   regressions) — the dashboard's value is a feature-gap map for the
   roadmap, not a pass/fail gate.
