# v1.5 Controller（纯 CSS 路径）设计

> 日期：2026-07-06
> 范围：v1.5 上半场。原 roadmap v1.5 = Controller + Gear + Transition 三件套，经 brainstorm 拆分：
> - **本期** = Controller（纯 CSS 路径）+ 标准 CSS `transition` 动画
> - **砍掉** = Gear（CSS 属性选择器 + 动态 API 已覆盖，YAGNI）
> - **拆出 v1.5-b** = Transition（时间线，与 Controller 正交）
>
> 本 spec 是设计契约。实现细节（字段名/算法）实现时按真实约束调。

---

## 0. 背景与拆分理由

### 0.1 三件套是什么（fgui 模型 + LoomGUI 适配）

- **Controller** = 状态机：具名，持 N 个 page，任意时刻选中一个 `selected_index`。纯状态，自己不改 UI，靠 CSS 属性选择器 rematch 驱动样式。典型：标签页/弹窗显隐/分页/选中态。
- **Gear** = 状态→属性映射：每节点绑一个 Controller，存 `{page → 属性值}`，切页时 kill 旧 tween + 提交插值 tween。fgui 有 10+ 种（Display/Xy/Size/Look/Color/FontSize/...）。
- **Transition** = 时间线编排器：纯数据 `items: Vec<TransitionItem>`，`Play()` 翻译成 tweener 提交 TweenManager。倒放/循环/hook。与 Controller 正交（不同层）。

依赖关系：Controller 是状态源；Gear 绑 Controller（紧耦合对）；Transition 独立，可被 Controller 经 `PlayTransitionAction` 触发（软依赖）。三者都不自驱，全往 TweenManager 提交/kill tween（LoomGUI 单一动画时钟不变量）。

### 0.2 为什么砍 Gear

`[data-page]` 属性选择器 + `transition`（CSS 路径）和 Gear 功能高度重叠。LoomGUI 比 fgui 多两件武器（CSS cascade + 动态 API `set_src`/`set_text` + `on_changed`），进一步压缩 Gear 独特价值：

| 切页要改的东西 | CSS 路径 | Gear 独特价值 |
|---|---|---|
| opacity / transform / display / color / font-size | ✅ `[data-page]` 选择器 + `transition` | 无（冗余） |
| 图片 src 切换 | ❌ CSS 表达不了 | 声明式映射表 |
| 文本内容切换 | ❌ CSS 表达不了 | 声明式映射表 |

fgui Gear 六种里五种被 CSS 取代，剩 src/text 也能用 `on_changed` + `set_src`/`set_text`（数据驱动）或多元素兄弟 + CSS 显隐（声明式、纯 DSL、AI 可预测、Chromium 预览保真）覆盖。Gear 整套机制 YAGNI，砍。

### 0.3 src/text 切换的两条路（都不用新机制，写进 spec 当 AI/driver 指引）

- **路 A · driver 代码**（1 元素，内容在代码切）：`on_changed(prev, new)` → driver 调 `set_src`/`set_text`。适合数据驱动内容。代价：映射在 C# 代码，AI 看 DSL 看不到。
- **路 B · 多元素兄弟 + CSS 显隐**（N 元素，纯 DSL）。节点身份标记用 **class**（`.show-0`），不用 `data-show` 属性——通用属性匹配本期不支持（§6 只匹配 data-controller/data-page）：
  ```html
  <div data-controller="icon" data-page="0">
    <img class="icon show-0" src="a.png">
    <img class="icon show-1" src="b.png">
  </div>
  ```
  ```css
  .icon { display: none; }
  [data-controller="icon"][data-page="0"] .show-0 { display: flex; }
  [data-controller="icon"][data-page="1"] .show-1 { display: flex; }
  ```
  适合静态每页内容。纯 HTML+CSS，AI 全见 + Chromium 预览保真。代价：N 冗余元素。

**指引**：AI 遇 per-page 图标/固定文案优先路 B（声明式、可预测）；运行时数据驱动内容走路 A。

## 1. 数据模型 + 声明 + 寻址

### 1.1 Controller 对象

最小化，砍 fgui 的 `page_ids`（无编辑器，页面集合对匹配无用，YAGNI）：

```rust
struct Controller {
    mount_node: NodeId,      // 带 data-controller="..." 的元素
    selected_index: i32,     // 当前页；-1 = 无选中（对齐 fgui 默认）
}
// name 不存对象里——name 只在挂载子树内局部有意义，作 HashMap key 局部使用
```

### 1.2 声明来源（HTML → 打包期 → registry）

- 打包器扫 HTML `data-controller="X"` 属性 → 记录 `(name, mount 节点路径, initial_selected_index)`。
- `initial_selected_index` 取 mount 元素的 `data-page` 属性（让 AI 在 HTML 写初始页，Chromium 预览认）；未写默认 0。
- 运行时 `load_package`/`instantiate` 建 Controller 对象塞进**按挂载 NodeId 寻址的 registry**。

### 1.3 寻址：句柄封装（解决 instantiate 复用）

**registry 按挂载 NodeId 寻址**：`HashMap<NodeId, Controller>`。name 只在挂载子树内局部有意义（CSS `[data-controller="tab"]` 本来就按 DOM 子树匹配，一致）。

driver API（FFI + C#）：
```
get_controller(mount_node_id, name) -> ControllerHandle   // 在某实例挂载子树内找名为 name 的 Controller
set_selected_index(handle, idx)
get_selected_index(handle) -> i32
register_changed_callback(handle, cb)                      // on_changed 按 handle 回调
```

- `ControllerHandle` 内部 = mount NodeId（+ 校验）。
- 多次 instantiate 同一组件 → 各有独立挂载 NodeId → 各有独立 Controller，**driver 不用改名**。与 fgui `parent.GetController("tab")` 一致（fgui Controller 也是组件作用域）。
- driver 拿到 handle 后缓存，后续 set/get 用 handle，不再用全局 name。

### 1.4 匹配器集成（关键，不写回属性）

匹配器评估 `[data-page="1"]` 时，从当前节点**回溯祖先**找最近的 `data-controller` 声明 → 查该挂载点的 `selected_index` → 比较。**不在节点上写 data-page 属性**——状态只存在 Controller 对象里，匹配器按需查。避免运行时改节点属性状态，也不和打包期 base_style 的 data-page 初始值打架。

> Chromium 预览侧，JS polyfill 把 `selected_index` 写到 mount 元素的 `data-page` 上触发原生 CSS 匹配——预览的"写属性"是 polyfill 行为，不是核心实现。

## 2. 切页数据流 + tick 时序

```
driver 调 set_selected_index(handle, 1)   [FFI，两 tick 之间]
  → core 改 registry 值 + 派发 on_changed
  → 下一帧 tick：
      ① tween 推进（写 override 值，见 §8）
      ② rematch_pseudo_classes（每帧全量重 cascade，现成）
          → 匹配器遇 [data-page] 时查 registry 的 selected_index
          → 重算命中节点 style
          → 若声明 transition 且有旧值 → 走 tween（override 层）；否则瞬切
      ③ solve（若 layout 属性变）→ ④ compute_world_transforms → ⑤ build_render_nodes
  → 视觉生效在 FFI 调用的下一帧（1 帧延迟，和所有跨 FFI 状态变更一致）
```

- `set_selected_index` **不用标 dirty**——rematch 本来就每帧全量重算，Controller 只需让 selected_index 可被查到。搭便车成立。
- 切页 kill 语义（见 §8.3）：切页触发 cascade 重算，若属性正被 tween → kill 旧 tween + 从当前值 tween 到新目标（不跳变）。

## 3. 多 Controller 共存 + 嵌套

- **一个元素挂一个 Controller**（`data-controller` 单值，不做空格多值——YAGNI）。多 Controller = 多个挂载元素（嵌套或兄弟）。
- **嵌套天然支持**：`[data-page]` 匹配器回溯找**最近**的 `data-controller` 祖先 → 内层 Controller 自动管自己子树，外层管不到内层子树（CSS 就近原则）。
- name 在挂载子树内局部唯一即可（同组件内不重名）。不同实例（instantiate 复用）同名不冲突——按 NodeId 寻址。

---

## 4. on_changed 事件 + FFI

- Controller 切页派发 `on_changed(prev_index, new_index)`，**pull 模式**（对齐现有 `borrow_events`，全代码库无 Rust→C# 回调）。
- 核心存 `pending_controller_events: Vec<ControllerChangedEvent>`（场景级），FFI 暴露 `borrow_controller_changed_events(h, out_len) -> *const u8`（坑 39：out_len 是 count 非字节；返回 `&[ControllerChangedEvent]` 借用，下 tick 失效）。`ControllerChangedEvent { mount_node: u32, prev: i32, new: i32 }` `#[repr(C)]`。
- driver 用途：① 路 A 切 src/text ② 路线 B 多元素已由 cascade 处理，driver 不用动 ③ 将来触发 Transition（v1.5-b）。
- **轮询兜底**：`get_selected_index(handle)` 保留，driver 也可不订阅事件直接轮询。
- **不做** `register_changed_callback`（push 模式）——代码库零 Rust-stored 函数指针先例，IL2CPP 风险高，pull 模式已够。

## 5. 打包期产物

- **静态**：`data-controller` + 初始 `data-page` → 打包器扫 `ElementData.attrs`（已捕获 data-*）→ 发 Controller 元数据进 pkg.bin：`ControllerEntry { name, mount_node_idx: u32, initial_selected_index: i32 }`。`mount_node_idx` 用组件内局部下标（同 `TemplateNode.parent_idx` 语义），`instantiate` 时经 `id_map` 重映射成活 NodeId。`Node.data_controller: Option<String>` 字段建树时填（照 draggable/tabindex 先例）。
- **动态规则表**：含 `[data-controller=...]`/`[data-page=...]` 的选择器规则进 `DynamicRuleSection`。**`extract_dynamic_rules` 分流判据须扩展**：当前只把含伪类的规则归动态；要加"含属性选择器也归动态"——否则 `[data-page]` 规则会被烤进 base_style（错）。
- **pkg.bin 版本**：加 ControllerSection + `TemplateNode.data_controller` → **formatVersion 12→13**（spec 草稿原写 8→9 是 stale，实码已是 12）。约定 MIN==MAX 同步升 13（无迁移器，旧包拒绝+重打）。单文件 `loomgui_core/src/asset/mod.rs` 读写都在这里。
- **包加载**：`load_package`/`instantiate` 读元数据 → 建 registry。`instantiate` 多次克隆同一组件 → 各自独立 Controller（按 NodeId 寻址，不冲突）；`mount_node_idx` 经 `id_map[mount_idx]` 映射成该实例活 NodeId。

## 6. 属性选择器地基（主要工作量）

§4.2"属性选择器归 class 级"当前是**文档漂移**——代码零实现。Controller 要 `[data-controller="tab"][data-page="1"] .panel`，必须先建属性选择器：

1. **解析器**（`parse/selector.rs`）：char 循环加 `[...]` 括号解析，支持 `[attr]` / `[attr="val"]`（先不做 `~=`/`^=`/`$=`/`*=`，YAGNI）。
2. **`Compound` 加 `attrs: Vec<AttrSelector>`**（`{name, op: Exists|Eq, value}`，bincode 可序列化，进 pkg.bin 动态规则表）。specificity 每个属性选择器 +1 进 b 桶（兑现 §4.2）。
3. **`Node` 加 `data_controller: Option<String>` 字段**——照 `draggable`/`tabindex` 先例（HTML attr → 专用字段），**不**加通用 attrs map（YAGNI，现在只匹配 data-controller）。`data-page` 不存节点（状态查询，见 4）。
4. **匹配分两种语义**（`compound_matches_with_state`）：
   - `[data-controller="tab"]` → 字面 attr 匹配 `node.data_controller == Some("tab")`。
   - `[data-page="1"]` → **状态查询**（同 `:hover` 性质）：从当前节点向上回溯找最近 `data_controller` 祖先 → 查 registry 该 Controller 的 `selected_index` → 比 == 1。matcher 函数已收 `&Scene`，registry 作 Scene 字段可访问。
   - 其他 `[attr]` → 节点不带 → 不匹配（等效"没这个 class"）。

**额外红利**：属性选择器是通用 CSS 能力，建一次以后任何 `[data-*]` 选择器都能用（不只 Controller），长期利好 AI 可预测性。

## 8. 动画（标准 CSS `transition`）

引入标准 CSS `transition` 属性（**不是** `-l-transition`——自创标记违反 §3.1 命名约定 + 伤 AI 可预测性 + Chromium 预览不认，已否决）。一套机制覆盖 Controller 切页 + `:hover`/`:active` + 任何状态变化。

### 8.1 围栏
- 加 `transition` 属性：标准 CSS 语法 `transition: <prop> <dur> <ease> <delay>`。先支持单属性或 `all`，简写解析。围栏外值静默忽略（`apply_decl` 返 false）。

### 8.2 机制 + runtime_overrides 层
- cascade 重算某属性时，若该属性声明了 `transition` 且**旧值存在**→ 不直接写新值，而是 kill 旧 tween + 提交 tween（old→new, dur, ease）给 TweenManager，`on_update` 写回。无旧值（首次）或 dur=0 → 瞬切。
- **runtime_overrides 层 = 现有 `AnimTable`**（scene/node.rs，opacity/transform/bg_color/text_color 四通道 Option replace-override）。`final = cascade ∘ anim_override`，在 compute_world_transforms + build_render_nodes 5 处 `unwrap_or` 合并。**不新建层**。
- **可动画通道 = `TweenProp` 六种**（Opacity/Translate/Scale/Rotation/BgColor/TextColor）。`transition` 只对这六种生效；其他属性变化（display/width/flex 等 layout 字段）**瞬切**（`TweenProp` 无 layout 变体，anim 永不触发 solve）。`transition` 围栏先支持 `opacity`/`color`/`background-color`/`all` 四种 prop 名（transform 矩阵分解本期不做，YAGNI）。
- **tick 时序**：tween 推进在 tick 第①步（现有），写 anim override 值；⑥rematch 算 cascade 值并检测通道变化→产 transition 请求；rematch 后 Stage drain 请求→kill+提交新 tween。

### 8.3 切页 kill 语义
Controller 切页触发 cascade 重算，若属性正被 tween → kill 旧 tween + 从当前值 tween 到新目标（不跳变）。这是 fgui Gear 切页的标准语义。`on_changed` 在 kill+新 tween 提交后派发。

- Gear（砍，CSS + 动态 API 取代）。

- `transition` 的多属性逗号分隔列表（先单属性/`all`，YAGNI）。

9. `:hover` 颜色/尺寸 `transition`（回归+新增）。
10. 切页中途再切页（kill 旧 tween，从当前值过渡到新目标，不跳变）。

## 11. 前向兼容（v1.5-b Transition）

Controller 与 Transition 在不同层，正交：
- Controller = 状态→cascade 重算（base + dynamic rules）。
- Transition = 时间线→TweenManager 写属性（runtime_overrides 层）。
- 唯一耦合：Controller.on_changed → driver → Transition.Play（v1.5-b）。
- runtime_overrides 层本期为 `transition` 建好，v1.5-b Transition 直接复用同一层写值。

不阻塞 Transition。唯一注意：tween 写属性优先级 > cascade（override 层语义），已在 §8.2 明确。
