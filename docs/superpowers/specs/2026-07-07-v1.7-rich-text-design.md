# v1.7 富文本（简化 inline flow + display:block desugar）设计

> 状态：设计待审（brainstorming 产出）。依据见 `docs/roadmap/rmlui-research.md §1.2/§1.3/§5.2`、`docs/roadmap/roadmap.md §2.2`、以及本轮三份对标深读报告（RmlUi IFC 算法 / RmlUi 富文本特性 / FairyGUI GRichTextField）。
> 范围：v1.7 = 富文本叶子（简化 inline flow）+ `display:block` desugar 到 flex+rich 叶；功能 = 样式分段 / 行内图（含 emoji-图片）/ 超链接 / 下划线删除线。**不碰**字体效果（v1.8）、彩色字形字体（v1.8+）、完整 CSS IFC。
> 不碰代码直至本 spec 经 writing-plans 落成任务计划。

---

## 1. 背景与目标

v1.6 把文本光栅搬进核心后，文本已是 `NodePayload::Mesh`（program=1，每字形 quad + 核心 GlyphAtlas UV + per-vertex color）。但**每个文本节点仍是单样式**（一种颜色 / 字体 / 字号）。游戏 UI 的真实需求——聊天（多色昵称 + emoji + 链接）、物品描述（多色属性 + 行内图标 + 斜体描述）、tooltip——都需要**同一段文本内多样式 + 图文混排 + 超链接**。这就是 v1.7 富文本。

**v1.7 目标**：在不破坏"div 永远 flex、行内混排编译期报错"核心不变量的前提下，让一段文本支持 inline flow（多样式 run + 行内图 + 链接 + 装饰线）。

**收益**：聊天/物品描述/tooltip 上线必备；建在 v1.6 atlas 之上（per-glyph 顶点色多色、per-run font_id/size_px 多字号多字体，零 atlas key 改动）。**不**做完整 CSS IFC、字体效果、彩色 emoji（均见 §3 非目标）。

---

## 2. 关键决策（brainstorming 定稿，含理由）

### 2.1 简化 inline flow，不做完整 CSS IFC

**决策**：实现"覆盖可预测常见情况"的简化 inline flow（扁平 token 流 + 单遍断行 + max-baseline-per-line），**不**实现完整 CSS IFC（多级 baseline 协商 / vertical-align 全集 / UBA 双向 / 嵌套 inline-box baseline 链）。

**理由（直击项目 #1 原则：AI 可预测性）**：AI 对 inline flow 的**概念**熟练，但完整 IFC 的**真实渲染**（baseline 协商、vertical-align、bidi）连人都难心算——AI 更难预测。简化模型（"行高 = 该行最高字，图坐 baseline"）是 AI 能心算的规则，在可预测性上**优于**完整 IFC。三份调研独立收敛于此（fgui 10 年游戏 chat 实战验证的正确简化）。

### 2.2 叶子封装运行时 + `display:block` desugar 的 DSL 表面

**决策**：运行时富文本是**叶子 NodeKind**（inline flow 封装在其 measure/build 里，div 永远 flex 不破）。DSL 表面让 AI 写 CSS 标准的 `<div style="display:block">...inline HTML...</div>`，**打包器 desugar** 成 flex div + rich 叶。

**理由**：拿到 A（结构化浏览器式）的 DSL 红利（AI 写 CSS 标准 `display:block`，零额外学习，最可预测）+ B'（叶子封装）的运行时红利（保 div=flex 铁律、inline flow 隔离在叶里不纠缠主引擎）。desugar 是编译器成熟模式（语法糖展开），界定紧则有界（见 §2.3）。

### 2.3 界定紧：`display:block` div 只装 inline 内容

**决策**：`display:block` div 只允许 inline 内容（文本 + `b/i/u/s/span/a/img` + `br`）。**禁止** block+inline 混排、嵌套 block div、匿名 block box。结构（分段/列/行/卡片）走 flex（LoomGUI 强项），rich 叶当叶子叠在 flex 里。

**理由**：让 desugar 保持一条机械规则（block div + inline 内容 → flex div + 单个 rich 叶），不随功能膨胀。要分段就用 flex 列叠多个 block-div——这正是游戏 UI 富文本的真实形态（实例见 §4）。

### 2.4 desugar 三护栏

1. **语义保持（最重要）**：desugar 必须可证明地保持语义——AI 在 DSL 层预测的渲染 = 实际渲染。靠 `fence_contract` 测试锁：给一批 `display:block` 富文本 DSL，锁 IR 展开结果 + 渲染 snapshot。
2. **block div 剥离 flex 属性**：`display:block` 是 block 容器，desugar 时 strip/拒收 flex 属性（`justify-content/align-items/flex-grow` 等），避免"AI 在 block div 写 flex 属性、desugar 后变 flex 行为"的泄漏。
3. **诊断双视**：dump 工具同时显示 DSL 源 + desugar 后的 IR，消除排查翻译缝（扩 `dump_rich` example）。

### 2.5 measure / build 分离（守单 solve + 纯 measure 不变量）

**决策**：富文本叶的 `measure` 跑 inline flow 算**尺寸**（每行宽 + 行高 + 总高，纯函数零副作用、可被 taffy 反复调，结果按 available_width 缓存）；`build` 阶段**消费** measure 缓存的 flow（最终宽度）产 mesh quad 列表 + fragment 命中矩形，atlas `ensure` 副作用只在 build。

**理由**：taffy 一次 solve 可能多次调 measure（max/min/definite），measure 必须纯函数零副作用（RmlUi IFC 边排边写回 DOM 的模式正是此处冲突，不可照搬，见调研报告 IFC §5）。v1.6 文本已是 measure（`TextLayout::measure`）+ render（`build`）分离，富文本沿用。build 拿 taffy 最终定的宽度，复用 measure 对该宽度的 flow 缓存（命中则不重算，未命中重跑一次）。

### 2.6 分期边界

- **字体效果**（描边/发光/阴影/渐变）→ **v1.8**。atlas key 的 `effect_sig` 已预留（v1.6 恒 0），v1.8 填 `hash(effect_type, params)`。
- **彩色字形字体**（COLR/CBDT，Unicode emoji）→ **v1.8+**。要换 FreeType + RGBA8 atlas（ab_glyph 只出灰度），重。
- **emoji 当图片**（国内游戏实际形态——自有表情包 PNG）→ **v1.7**。就是行内图片，第二段白送，无额外成本。

## 3. 非目标

- **完整 CSS IFC**：多级 baseline 协商、vertical-align 全集（Sub/Super/TextTop/TextBottom）、UBA 双向、嵌套 inline-box baseline 链、inline-block 嵌套、float 环绕。简化版只做 baseline（默认）+ middle + 绝对像素 length。
- **字体效果**：描边/发光/blur/shadow/渐变字体。v1.8（atlas CPU 后处理）。
- **彩色字形 emoji**：COLR/CBDT。v1.8+（FreeType + RGBA8 atlas）。
- **复杂 shaping（rustybuzz）/ BiDi / RTL**：仍砍（亚洲首发）。
- **富文本内嵌可交互控件**（`<input>/<select>/<button>` in flow）：游戏罕用 + 与"叶子无子 Node"冲突，砍（fgui 也罕用）。
- **block+inline 混排 / 嵌套 block / 匿名 box**：§2.3 界定禁止，编译期报错。

## 4. DSL 设计（AI 写什么 + desugar 规则 + 围栏改动）

### 4.1 AI 写的 DSL（CSS 标准形态）

聊天卡片：
```html
<div style="display:flex; flex-direction:column">
  <div style="display:flex; flex-direction:row">
    <img src="avatar"/>
    <div style="display:block">
      <span style="color:gold">大神</span><span style="color:#888;font-size:12">[武林盟]</span>
    </div>
  </div>
  <div style="display:block">
    获得 <img src="sword"/> <a href="item://sword">烈焰之剑</a> x1！
  </div>
</div>
```

物品 tooltip：
```html
<div style="display:flex; flex-direction:column; gap:4">
  <div style="display:block; text-align:center"><span style="color:gold;font-size:18">【传说】烈焰之剑</span></div>
  <div style="display:block">攻击 <b style="color:#3f6">+120</b>　防御 <b style="color:#3f6">+50</b></div>
  <div style="display:block"><span style="color:#aaa;font-style:italic">"传闻此剑蕴含烈焰之力..."</span></div>
  <div style="display:block"><a href="detail">查看详情</a></div>
</div>
```

结构 = flex（列/行叠），富文本 = `display:block` div 当叶子。AI 写起来 ≈ 写网页（`display:block` 是 CSS 标准玩法）。

### 4.2 desugar 规则（打包器，界定紧）

`display:block` div 含 inline 内容 → 展开为 flex div（`flex-direction:column`）+ 单个 RichText 叶子节点，叶子的 runs = inline 内容解析产物。

- block div 的**盒属性**（background/border/padding/margin/width/height/text-align/overflow）留在 flex div 上。
- block div 的**文本属性**（color/font-size/font-weight/font-style/font-family/line-height/text-decoration/vertical-align）级联进 rich 叶作 base_style。
- **strip flex 属性**（justify-content/align-items/flex-*/order/gap）——block 容器不该有；围栏直接拒收 block div 上的 flex 属性（编译期报错，比静默 strip 更可预测）。
- block div **只允许 inline 内容**：出现块级子（`div`/结构元素）与 inline 混排 → 编译期报错。

### 4.3 围栏改动（fence_contract 锁）

- `div` 加 `display: block` 合法值（现有 flex/缺省）。`block` div 受 §4.2 约束。
- **富内容标记子集**（block div 内 / 动态 set_rich_text 串）：见 §6.1 白名单。围栏外标签/属性编译期报错（同现有围栏哲学）。
- desugar 是打包期变换；runtime/IR 层 div 永远 flex（铁律不动）。

## 5. 架构总览（数据流）

```
DSL: <div style="display:block">inline HTML</div>
  → 打包器 desugar（§4.2）→ IR: flex div + RichText 叶 { runs: Vec<RichRun> }
  [静态：打包期解析 markup → runs；动态：runtime set_rich_text(node, markup) → 核心解析 → runs]

Rust 核心（RichText 叶）:
  measure(available_width)  ← taffy MeasureFunc，纯函数，可反复调
    ├─ runs 单遍断行（CJK 逐字 / Latin 逐词，复用 unicode-linebreak）
    ├─ max-baseline-per-line + strut 半行距 → 每行高
    └─ 返 (content_width, content_height)；零副作用（不光栅、不写 atlas）
  build（渲染期，消费 measure 缓存的 flow）:
    ├─ 每字形 ensure 进 GlyphAtlas（v1.6，key=(font_id,gid,size_px,0)）
    ├─ 产 Mesh quad：position(baseline+advance) + UV(atlas) + per-vertex color(run.color)
    ├─ 装饰线 quad（underline/strike，offset 用字体 metrics）
    ├─ 行内图 quad（image atlas，baseline/middle 对齐）
    └─ 收集 Vec<RichFragment{rect, link_id}> 供命中

FFI:
  ├─ 富文本 = NodePayload::Mesh（program=1），走 v1.6 mesh_arena，**blob 不 bump 版本**
  └─ 命中扩展：节点命中后查 fragment 矩形 → rich_link_id（§8）

Unity 后端:
  ├─ 渲染：Mesh（program=1）走 v1.6 SyncFontAtlas + Sprite 路径，**零新渲染代码**
  └─ 链接事件：LoomEventHandler 读 rich_link_id → 派发 onClickLink（业务侧）
```

**核心不变量守住**：measure 纯函数（光栅/atlas 副作用在 build）；tick 时序不变；div 永远 flex（runtime/IR）；坐标系不变；代际 NodeId 不变。

## 6. 核心组件设计

### 6.1 富内容标记子集（markup whitelist）

| 标签 | 语义 | style/属性 |
|---|---|---|
| `b`/`strong` | 粗体 | font-weight: bold |
| `i`/`em` | 斜体 | font-style: italic |
| `u` | 下划线 | text-decoration: underline |
| `s`/`del` | 删除线 | text-decoration: line-through |
| `span` | 任意内联样式 | style: color/font-size/font-weight/font-style/text-decoration/vertical-align |
| `a` | 超链接 | href（业务侧读，核心不导航） |
| `img` | 行内图 | src/width/height/vertical-align |
| `br` | 强制换行 | — |

嵌套标签（`<b>ab <i>cd</i> ef</b>`）→ **flatten 成带继承上下文的 run 序列**（栈式 cascade：父 base → 子覆盖，每 run 携带完整 effective style，不保留嵌套结构）。`<a>` 跨嵌套时 link_id 归属最内层 `<a>`。

### 6.2 RichRun 模型

```rust
struct RichRun {
    kind: RichKind,
    color: [f32; 4],       // per-run 色（per-glyph 多色靠多个 run，非 per-glyph 字段）
    font_id: u32,          // v1.6 FontTable font_id
    size_px: u16,          // 进 atlas key（per-size 分片）
    weight: FontWeight,
    style: FontStyle,
    decoration: TextDecoFlags,  // UNDERLINE / LINE_THROUGH
    link_id: Option<u32>,  // 属于某链接（<a> 内）
}
enum RichKind {
    Text { text: String },          // 同 style 的子串
    Image { src: String, w: f32, h: f32, vertical_align: VAlign },
}
```

> per-run color（非 per-glyph）对应 RmlUi per-ElementText 单色（调研报告特性 §2）。v1.6 atlas key 已含 font_id/size_px，**零 key 改动**；per-run color 走 per-vertex（v1.6 已支持）。

### 6.3 markup 解析器（核心模块，runtime 可用）

**设计决策**：核心提供一个**专用的轻量 rich-markup 解析器**（只认 §6.1 子集），**不**走 scraper 全文档解析器。理由：

- 富文本有**动态**用例（chat/物品描述运行时拼串），需 runtime 解析 → markup 解析器必须在 runtime 可用。
- CLAUDE.md "运行时不带 HTML 解析器" 指的是**结构文档解析器**（scraper，parse-feature 门控）；rich-markup 是**子集微型解析器**，是另一回事，是动态富文本的正当需求。
- 静态富文本：打包器也调同一个解析器（resolve_styles 阶段，§4.2 desugar 后），产物存进 RichText 叶的 runs。

解析产物 = `Vec<RichRun>`（flatten，不进 scene graph，不进 taffy）。容错：未闭合标签 / 围栏外标签 → 编译期报错（静态）或安全降级（动态，chat 输入不可信，绝不能 panic——坑 102）。

### 6.4 简化 inline flow（measure + build）

**断行**（搬 fgui `BuildLines2` + RmlUi `ElementText::GenerateLine` 算法思想）：
- 单遍逐 token：CJK 每字可换行（unicode-linebreak），Latin/数字按词（`word_possible` + 词长跟踪，超长词放弃整词移动）。
- `available_width` 来自 taffy（measure 入参）；超宽且本行非空 → 开新行。
- `<br>` / `\n` 强制换行。

**baseline / 行高**（max-baseline-per-line + strut，搬 RmlUi `LineBox::DetermineVerticalPositioning` + `GetStrut`）：
```
line_ascent  = max(run.font_ascent  for run in line)   // 不同字号取 max
line_descent = max(run.font_descent for run in line)
line_height  = max(strut, line_ascent + line_descent)  // strut = half-leading 模型
每 run 的字形 y = line_baseline + vertical_align_offset
```
- 图片默认 baseline = 底边（descent=0, ascent=height）；`vertical-align: middle` → 0.5×(ascent-descent) - 0.5×img_h；`length` → 绝对像素偏移。
- half-leading（RmlUi `InlineBox.cpp:22-30`，4 行公式）直接抄，CSS 标准、AI 可预测。

**build 产 mesh**（每字形 quad，搬 RmlUi `FontFaceLayer::GenerateGeometry` baseline→quad 转换）：
- 字形 quad 左上 = baseline + (bearing.x, -bearing.y)；尺寸 = 光栅 px（v1.6 GlyphRect.px_w/px_h）；UV = atlas 槽；顶点色 = run.color。
- 装饰线：underline y = baseline + font.underline_position；line-through y = baseline - 0.5×x_height；厚度 = font.underline_thickness（≥1px）；色 = run.color；UV=0（纯色，不进 glyph atlas）。
- 行内图：image atlas（非 glyph atlas）查 src；quad 按 w/h + vertical_align 偏移；advance = w + spacing。

> **kerning**：v1.6 已重开（搬字体后 quad==ttf bbox 安全）。富文本沿用 measure 的 kern，多 run 边界 kern 可选（首版跨 run 不 kern，简化）。

### 6.5 desugar pass（打包器）

打包器 resolve_styles 阶段后插一步：扫 `display:block` div → 按 §4.2 展开。fence_contract 锁展开规则 + 拒收场景（block div 上 flex 属性 / block+inline 混排）。

## 7. 命中与事件（超链接）

**核心命中扩展**（搬 RmlUi fragment-rect + fgui 多 rect selection shape）：
- RichText 叶在 build 期产 `Vec<RichFragment { rect: LayoutRect, link_id: Option<u32> }>`（每个链接跨行拆多个 rect，首行/中行/末行分段，fgui `GetLinesShape` 范式）。
- 核心命中（现有节点级 AABB，`hit.rs`）：命中 RichText 叶后，遍历其 fragments（经 world_matrix 变换），命中的 fragment 的 `link_id` 作为命中附加数据。
- **不需要**"鼠标→字符索引"反查（RmlUi 也没做，调研报告特性 §3）。

**事件路由**（业务侧 C#，同现有架构）：LoomEventHandler 见 `rich_link_id > 0` → 派发 `onClickLink(link_id/href)`。`<a>` 的 href 存 run 属性，核心不导航（同 RmlUi——业务方挂 onclick）。

## 8. FFI 契约

- **frame blob 不 bump 版本**：富文本 = `NodePayload::Mesh`（program=1），走 v1.6 mesh_arena。富文本只是"更多 mesh 数据"，blob 列/结构零改。✅（比 v1.6 的 blob v10 轻得多。）
- **动态富文本 API**（新增，命令式，对齐 v1.x 动态树 set_text/set_src 惯例）：`loomgui_node_set_rich_text(nodeId, markup_ptr, markup_len)` —— chat/物品描述运行时设富文本串，核心调 §6.3 解析器 → runs → 置 dirty 重 measure/build。ptr+len（坑 16，不靠 NUL）；FFI 入口不 panic（坑 102：nodeId 失效/scene=None 早返）。静态富文本（DSL）走打包器，不经此 API。
- **命中扩展**（新增）：两选一（plan 定）——
  - (a) hit 结果 struct 加 `rich_link_id: u32`（0=无链接），或
  - (b) 独立 pull FFI `loomgui_node_rich_link_at(nodeId, local_x, local_y) -> u32`（双调/早返 0，对齐 NativeHost 查询惯例，坑 102 不 panic）。
  - 倾向 (b)：hit 结果不改 ABI，link 查询独立通道（复用 NativeHost-style 按 nodeId 查询）。
- csbindgen 镜像同步（坑 35）；FFI 入口不 panic（坑 102）。

## 10. 分阶段（v1.7 内部 task，非版本拆分）

scope 收窄后 v1.7 是一个内聚特性，**不拆 a/b/c 子版本**。但 task 分段交付 + 每段 PlayMode 验收（坑 131-133 教训：CSS 语义集成只在 PlayMode 显现）：

- **MVP 段**：RichRun 模型 + rich-markup 解析器（静态打包期 + 动态 runtime 同一解析器）+ 简化 inline flow（measure/build）+ 样式分段（多色多字号粗斜体）+ `set_rich_text` 动态 API + desugar pass + fence_contract。
  - PlayMode 验：多色多字号文本换行正确、字距（kern）对、desugar 后渲染 = DSL 预期、`set_rich_text` 运行时换内容正确重排。
- **第二段**：行内图（baseline/middle）+ emoji-图片 + text-decoration（下划线/删除线）。
  - PlayMode 验：图标嵌文字对齐、下划线/删除线位置、emoji 表情包图。
- **第三段**：超链接（fragment 矩形 + 命中扩展 + FFI link 查询 + Unity onClickLink）。
  - PlayMode 验：跨行链接多 rect 命中、点击派发、hover 反馈。

依赖链：解析器 → measure → build →（图/装饰/链接）。desugar 相对独立（DSL 层）但需 RichText NodeKind 先在。

## 11. 测试与验收

**单测（核心）**：
- markup 解析：flatten 嵌套（`<b>a <i>b</i> c</b>` → 3 run 带 effective style）、围栏外标签报错、未闭合安全降级。
- inline flow measure：CJK 逐字断行 / Latin 逐词、max-baseline 多字号混排、strut 半行距、`<br>` 强制换行。
- inline flow build：每字形 quad position/UV/per-vertex color、装饰线 offset、行内图 advance。
- 命中 fragment：跨行链接多 rect、link_id 归属。
- fence_contract 门：`display:block` desugar 展开 + block div 拒收 flex 属性 + 混排报错。

**dump_rich example**（扩 `loomgui_core/examples/`）：直查 RichText 叶的 runs / 行 / baseline / fragment 矩形（不靠 PlayMode 猜）。

**PlayMode 验收（家里机，两台机串行）**：每段逐项过（§10）。重点：desugar 后渲染 = AI 写 DSL 的预期（语义保持护栏）；多色多字号字距；图标对齐；链接命中。

**stale .dll / 重打 pkg**：runtime 改（measure/build/解析器）改 .dll 即可；**desugar + markup 子集是 parse-time/打包器改，须重打 pkg**（坑 66）。

## 12. 风险与权衡

| 项 | 风险 / 权衡 |
|---|---|
| desugar 语义保持失败 | AI 预测 ≠ 渲染（破 #1 原则）。护栏：fence_contract 锁展开 + snapshot；dump_rich 双视。 |
| 简化 inline flow 边角粗糙 | 大图+小字单 baseline 对齐一般（图标顶天）。`vertical-align:middle` 补偿；完整协商推无限期（不做）。 |
| 动态 markup 解析器 robustness | chat 输入不可信。专用子集解析器 + 围栏外/未闭合安全降级，绝不 panic（坑 102）。 |
| measure 每帧重跑 flow 性能 | 缓存 + dirty（文本/宽未变则复用）；taffy 多次调 measure 走缓存。 |
| block div 上误写 flex 属性 | 围栏编译期拒收（比静默 strip 可预测）。 |
| 跨 run kern 缺失 | 首版跨 run 边界不 kern（简化）；单 run 内 kern 正常。可接受。 |
| 链接命中 AABB vs 字形级 | fragment 矩形级（非字符级），够用；选区类需求无限期不做。 |

## 13. 调研取证摘要（决策依据）

- **简化 > 完整 IFC**：fgui `BuildLines2`（`TextField.cs:723-952`）单遍逐字断行 + max-baseline-per-line（`UpdateLineInfo:954-988`）是 10 年游戏 chat 实战；RmlUi IFC 70% 绑 DOM 对象模型不可搬（`InlineBox.h:23-24` box 树镜像 DOM、`LineBox::Close`→`Submit` 边排边写回），算法本身可搬但完整 IFC 重量在 DOM 税。
- **per-run 色**：RmlUi per-ElementText 单色（`ElementText.h:90`、`ElementText.cpp:494`），per-glyph 多色靠多叶子 → 对应 LoomGUI per-RichRun。
- **链接命中 = fragment 矩形 AABB**：RmlUi `Element::AddBox` per line fragment（`Element.cpp:454-461`）+ `IsPointWithinElement` 逐 box 测试（`Element.cpp:545-564`），不依赖 DOM，可搬；fgui `SelectionShape` 多 rect（`SelectionShape.cs:77-92`）+ `GetLinesShape`（`TextField.cs:457-507`）跨行拆 rect。
- **baseline/strut**：RmlUi `GetStrut` half-leading（`InlineBox.cpp:22-30`，4 行公式）+ `DetermineVerticalPositioning`（`LineBox.cpp:197-293`）。
- **行内图 baseline**：RmlUi `InlineLevelBox_Atomic`（`InlineLevelBox.cpp:106-116`，ascent=height、descent=0 底边贴 baseline）+ vertical-align 公式（`:46-86`）。
- **装饰线**：RmlUi `GenerateDecoration`（`ElementText.cpp:545-567`）= 纯 quad，offset 用字体 metrics。
- **emoji=图片**：fgui `ParseText`（`TextField.cs:1039-1102`）codepoint→img 替换，国内游戏表情包就是这形态。
- **measure/build 分离**：RmlUi `GetShrinkToFitWidth` 二次格式化（`LayoutDetails.cpp:244-254`）与纯函数 measure 冲突 → LoomGUI measure 只算尺寸、build 才产 fragment。
- **标记 flatten**：fgui `HtmlParser` 格式栈（`HtmlParser.cs:336-360` Push/Pop TextFormat）原生支持嵌套 → LoomGUI flatten 成带继承 run。

完整证据见三份对标深读报告 + `docs/roadmap/rmlui-research.md §1.2/§1.3/§5.2`。

## 14. 不碰清单（别抄 / 已领先）

- **别抄 RmlUi inline-level box 树**（DOM 镜像）、**边排边写回**、**跨 block line-box chain**、**floats**、**shrink-to-fit 二次格式化**、**完整 vertical-align 全集 / UBA**——与 LoomGUI flex-only + 单 solve + 纯 measure 冲突。
- **别抄 fgui UBB 标记**（`[b][/b]`）——LoomGUI 是 HTML DSL，引 UBB 是倒退；用 HTML 子集。
- **别抄 fgui "图片/链接是子 DisplayObject"**——LoomGUI 叶子无子 Node；图烤进 mesh（合批）、链接走 fragment 矩形命中。
- **已领先勿动**：v1.6 核心 atlas / text-as-Mesh / per-vertex color / blob v10 / Unity SyncFontAtlas（v1.7 全复用）。
