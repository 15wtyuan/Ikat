# v1.4-a 家里机验收 bug 清单（2026-07-02）

## 背景

公司机 push v1.4-a（包加载模型重构，commit 262e0fb 等）后，家里机首次 `git pull` + Unity PlayMode 验收。**公司机本地有缓存（旧 dll / bindings.cs）掩盖了多个问题；家里机干净环境才暴露**。本清单记录今晚验收发现的 bug，供明天集中处理。

---

## A. 已修（本次 commit）

### A1. 公司机 commit 了旧 dll（262e0fb）
- **症状**：CS0117 `loomgui_stage_instantiate` 不存在 + CS1501 `load_package` 参数数不对
- **根因**：262e0fb 改 FFI 源码（`load_package` 加 name 参数 + 新增 `instantiate`），但 commit 进 git 的是**没重编的旧 dll**（`findstr` 查无 `instantiate` 导出）。`bindings.cs` gitignored（各机各 build，不跨机器同步）。公司机本地缓存的旧 dll/bindings 把问题盖住，家里机干净 pull 才暴露。
- **修**：家里机 `cargo build -p loomgui_ffi_c --release` 重 build + cp dll（`build.rs` 自动重新生成 `bindings.cs` 并落 Unity 目录）

### A2. EventType 命名空间遮蔽（LoomPackageManagerWindow）
- **症状**：CS0117 `EventType.DragPerform/DragUpdated` 不存在
- **根因**：`namespace LoomGUI.Editor` 里 `EventType` 解析到父 `LoomGUI.EventType`（runtime 枚举），遮蔽 `UnityEngine.EventType`。**`using EventType = UnityEngine.EventType;` alias 无效**——C# 名称查找规则：当前+父命名空间类型优先于 using alias。
- **修**：fully-qualify `UnityEngine.EventType.DragPerform/Updated`（4 处）

### A3. ExecuteAlways EditMode tick panic（打开场景闪退）
- **症状**：打开 Unity 场景闪退。`Editor.log`：`thread panicked at loomgui_core\src\stage.rs:421:41: load first` → `loomgui_stage_tick` → `thread caused non-unwinding panic. aborting` → Unity 进程崩
- **根因**：`LoomStage` 标 `[ExecuteAlways]` → EditMode 也跑 `LateUpdate` tick。v1.4-a 砍了 Awake 自动建 scene（改由 driver.CreateRoot 建），但 `LateUpdate` 只 guard `_stage==null`（handle 在），**没 guard scene 是否建成** → EditMode driver.Start 没跑、scene=None 时 tick → Rust `tick_and_render` 里 `.expect("load first")` panic → cdylib panic 拖垮宿主进程
- **修**：LoomStage 加 `_sceneBuilt` 字段，CreateRoot 成功置 true，LateUpdate 顶上 `if (_stage == null || !_sceneBuilt) return`

## B. 待修（v1.4-a 设计层，明天集中改）

### B1. hover/active 伪类刷新「时好时坏」
- **症状**：nav 按钮 `:hover` 变色 / `:active` 缩放「时好时坏」，点击后偶有反馈
- **诊断进展**：
  - F1 dump 显示 home 所有节点 `layout` + `world_matrix` 全正常 → **排除 transforms/layout**
  - `[HOVER-EVT]` log 显示 hit_test 在 Down 之后能命中 nav 按钮（`RollOver nav-controls @ design(247,139)`，落在按钮 rect 内）→ **排除命中错**
  - `:hover` 变色和 `:active` 缩放都不刷新（同性质）
- **嫌疑**：rematch 改了 style，但 `build_render_nodes` 的 dirty hash 没捕获伪类样式变化 → emit `Unchanged` → MirrorPool 不刷（帧相关 → 「时好时坏」）
- **待查**：`build_render_nodes` 的 dirty hash 是否覆盖 `:hover/:active` 引起的 style 变化；rematch 后 dirty_mesh 是否正确标记

### B2. 图片 path↔atlas sprite name 映射缺失（设计疏漏）
- **症状**：img 显示为白块（不显示）
- **诊断**：`[IMG]` log 显示 `atlases=1 found=null`（atlas 注册了但 `atlas.GetSprite("home")` 返 null）
- **根因**：v1.4-a 砍自建 atlas 改 Unity Sprite Atlas，但**没设计 path↔atlas sprite name 的映射契约**。`SpriteResolver.GetSprite` 取文件名去扩展（`"icons/home.png"` → `"home"`）查 atlas，启发式脆弱；atlas pack 后实际 sprite name 可能不匹配
- **附带（家里机已改）**：工程原没装 2D Sprite 包（manifest 缺 `com.unity.2d.sprite`）；png 原 import 成 Default Texture（`textureType:0`）。家里机已：装 2D Sprite 包 + png 改 Sprite（`spriteMode:1` Single）+ 建 `LoomShowcaseAtlas.spriteatlas` + 拖到 LoomStage `_spriteAtlases`。但 GetSprite 仍 null → path↔name 映射待设计修
- **设计修方向**：打包器/包管理器在打包期锁定 path→sprite name 映射进 manifest，运行时确定性查（不靠运行时取文件名猜）

### B3. overlay/层机制缺失（tips 被挤出）
- **症状**：点 tips-demo，toast 实例化成功（Console「tips 叠加显示」）但看不见
- **根因**：driver 建 `root(column) + ui_layer(flex-grow:1) + tips_layer`。tips_layer 想叠在 ui_layer 上（overlay），但 LoomGUI **无 `position:absolute`**（围栏外静默忽略），tips_layer 进 column 流被 ui_layer 的 flex-grow 挤到 root 底外（dump 证据：tips_layer `layout.y=1920`，root 高 1920 → 整个在底边外）。toast 挂 tips_layer 也在屏幕外
- **设计修方向**：LoomGUI 加 overlay/层机制（absolute 定位 / z-layer）；或 driver 妥协（transform 偏移 / 给 tips_layer 留空间）

### B4. 文字乱（随机重叠/上下错位）
- **症状**：完全随机，任何文字可能重叠/上下错位
- **诊断进展**：
  - F1 dump 显示 Text 节点 `layout` 全正常 → **排除节点级位置**（是 cluster 级字符位置乱）
  - `UploadMesh`（buffer 复用）清理正确：`Clear()` + 按 `seg.Verts.Length` 精确填 + `Mesh.Clear()` → **排除池子残留**（用户的「池子复用坏掉」怀疑，buffer 这层不成立）
- **嫌疑1（bug，但表现不符）**：`MirrorPool.cs:173 needRebuild = fontDirty || FontVersion 变`，**不看 dirty_text** → 文字内容变（SetText）后 mesh 不重建（显示旧字）。但这表现「不更新」，非「重叠/错位」
- **嫌疑2（最符合随机重叠/错位）**：Unity 动态字体 atlas rebuild 竞态。`TextRasterizer.BuildMesh` 当帧 `RequestCharactersInTexture` + 当帧 `GetCharacterInfo`。首次出现的字形（中文多）触发 atlas rebuild（`Font.textureRebuilt` → FontVersion++ → 全节点 needRebuild），rebuild 当帧 `GetCharacterInfo` 返抖动 box/UV → 字形 quad 位置错。随机 = 字形首次出现 + atlas rebuild 时机。fgui DynamicFont 也踩过
- **待查**：加 log 看 `GetCharacterInfo` 在乱时的 box/UV 返值；`needRebuild` 加 dirty_text 判断

## 教训（待补入 `docs/pitfalls.md`）

1. **公司机 push 前必须 clean build + 实测**：262e0fb commit 旧 dll 是因为公司机本地有缓存 dll/bindings 掩盖。家里机干净 pull 才暴露。push 前应 `cargo clean` + build + 跑一遍。
2. **csbindgen 生成物（`bindings.cs`）gitignored**：各机各 build，不跨机器同步。改 FFI 后必须本机 `cargo build -p loomgui_ffi_c` 重新生成 + cp dll。
3. **C# using alias 解不了父命名空间同名类型遮蔽**：`namespace LoomGUI.Editor` 里 `EventType` 必先命中父 `LoomGUI.EventType`，using alias 排在名称查找后面被遮蔽。解法只能 fully-qualify。
4. **cdylib panic = 宿主进程崩**：FFI 入口绝不能 panic（`.expect`/`unwrap`），任何 scene=None 都要优雅早返，不能拖垮 Unity。`tick_and_render` 的 `.expect("load first")` 是隐患，应改早返空帧（防御性）。
