## 0. 为什么有这一项

v1.4-a 收尾暴露两件事：
1. **tips overlay 被挤出**（B3）：v1 围栏排除 `position:absolute`，tips_layer 进 flex 流被 ui_layer 的 flex-grow 挤到屏幕外。v1.4-a 临时用 transform 偏移妥协（driver 内部污染），真覆盖式叠加要 absolute。
2. **无虚拟化列表**：背包/排行榜/邮件等"数据量可能上千"的列表，v1 只能手搓 div+scroll 全量建子节点，无 slot 复用——上千 item 全建+全渲染，性能崩。

两项同期做的原因：**虚拟列表的 slot 定位依赖 absolute**（slot 用 `position:absolute; top:real_y` 脱离 flex 流定位到真实 item 位置）。absolute 围栏一落地，列表直接用；分开做的话列表得先用 transform 妥协再迁移。两项协同。

**soft clip 不在本期**：现有硬矩形 CLIPPED（mask_context + _ClipBox）已能裁剪滚动容器视口溢出，是列表硬需求；soft clip（羽化）是视觉锦上添花，推 v2 和 shape mask/paintingMode 一起（roadmap §5.2 归类更合理：都是渲染特效类）。本期 = absolute 围栏 + 虚拟化列表两项。

## 1. position:absolute 围栏扩张

### 1.1 围栏新增

`apply_decl`（`loomgui_core/src/style/mapping.rs`）加 6 个 arm：

- `"position"` → 值 `absolute` 设 `taffy_style.position = Position::Absolute`；`relative` 显式设 Relative；`fixed`/`sticky`/其他 → 静默忽略（返 false，保持默认 Relative）。
- `"top"`/`"right"`/`"bottom"`/`"left"` → 解析长度，写 `taffy_style.inset` 对应边（`LengthPercentageAuto::Length`）；`auto` 不写（保持默认 auto）。

### 1.2 包含块

taffy 0.5.2 原生 `Position::Absolute` + `inset`，相对最近 positioned 祖先（`position:relative`/`absolute`）的 padding box；无 positioned 祖先相对初始包含块（根）。和 CSS 一致，零特判。

### 1.3 layout/render/hit 零改

taffy solve 自动处理 Absolute 项（脱离流、不占空间、inset 定位）。LoomGUI 各层照常消费 layout_rect：
- layout：`build` 只把 CSS 映射进 taffy_style，solve 照常。
- render：absolute 项照常产 layout_rect、走 world_transform、命中如常。
- hit：命中几何 = layout_rect 经 transform 变换 AABB，absolute 项照常。

### 1.4 inset + auto size 拉伸

CSS 规则：absolute 项同时设 `left`+`right` 且未设 `width` → 宽度由左右 inset 拉伸（`width = containing_block - left - right`）。taffy 0.5 原生支持此组合。**待家里机验证**——absolute 最易出 bug 处。

### 1.5 tips overlay 落地

撤 v1.4-a driver 的 transform 妥协（`transform:translate(0,-1920px)` + `height:1920;flex-shrink:0`）。tips_layer 改用：
```css
.tips_layer { position:absolute; top:0; left:0; width:100%; height:100%; }
```
ui_layer 恢复正常 flex 流，不再需要显式 1920 + flex-shrink:0。

### 1.6 围栏维护流程

1. `mapping.rs` 加 6 arm（~30 行）。
2. `fence_contract.rs` 翻转 2 测试：
   - `fence_out_props_return_false`：`("position","absolute")` 从"返 false"移除。
   - `position_absolute_does_not_break_flow`：从"返 false + position 不变"改为"返 true + position=Absolute + inset 生效 + 脱离流"。
3. `fence.md` §2 补 position 行标【实证】；§6 预览可信清单：absolute 从"不可信"移除（Chromium + taffy 都支持，可预览）。
4. `main-design.md` §3.2 翻转契约（absolute 现在脱离流）。
5. `roadmap.md` §1.2 同步。

### 1.7 parse-time 改动

`apply_decl` 操作 `ResolvedStyle`（打包期 `resolve_styles` 产物，进 `base_style`）。改 mapping 是 parse-time 改动——**须重编 .dll + 重打 pkg**（坑 66）。showcase 等现有 pkg 全部按新格式重打。

### 1.8 改动面

约 1 天。mapping.rs + 2 fence 测试改写 + 4 文档同步。纯 Rust + 文档。

## 2. 虚拟化列表（层 B'）

### 2.1 分层定调：核心不认识"列表"

**核心眼里没有"列表"这种节点**。一个列表在核心看来是：
- 一个普通 div（滚动容器，`overflow:scroll`）
- 下挂 N 个普通 div（slot，每个带 `reuse_key` 标记，`position:absolute` 定位）

核心只多管一件事：每节点一个 `reuse_key: u32` 字段。核心不知这 N 个 div 是"列表的槽"。

**这理顺了 main-design 的三处含糊**：
- §12.2 "核心做 slot 复用" → 核心做的是 reuse_key 字段传递 + content_size/scroll_pos/layout_rect 的 FFI 口子，不是"认识列表"。
- line 74 "代码层在 ScrollPane 上实现" → driver（代码层）在 ScrollPane 上实现 slot 映射/可见区间/尺寸补偿。
- line 580/592 "后端 slot 复用池" → 后端按 reuse_key 复用 GO。

三处统一为层 B'：核心提供通用能力（reuse_key + 3 FFI 口子），driver 管列表逻辑，后端按 reuse_key 复用。**与 roadmap §5.1 原意一致**（"核心维护固定数量可视槽...后端按 reuse_key 复用渲染对象"——reuse_key 是核心传的，"可视槽"是 driver 建的）。

### 2.2 slot 复用模型（roadmap §5.1 原意）

- **slot_id 稳定**（0..N）：driver 建列表时给每个 slot 设 `reuse_key = slot_id + 1`（0 保留为"无复用"）。
- **NodeId 变**：slot 换绑 item 时，driver `remove_node` 旧子树 + `instantiate` 新子树，NodeId 变。
- **reuse_key = slot_id**：后端按 reuse_key keying，slot 换内容时 NodeId 变但 reuse_key 不变 → **GO 复用不销毁重建**，只重建 mesh。
- **防花屏不变量自动满足**：新 NodeId 无上帧 hash → ChangeLevel::Full → mesh 重建。无需特殊处理。

### 2.3 核心改动

#### 2.3.1 reuse_key 字段
- `RenderNode`（`render/node.rs`）加 `reuse_key: u32`（0=无复用，>0=按 reuse_key 复用）。
- `Node`（`scene/node.rs`）运行时状态加 `reuse_key: u32` + `set_reuse_key` API。**打包期不存**（运行时字段，不进 pkg，不改包格式）。
- `build_render_nodes`（`render/mod.rs`）把 Node.reuse_key 拷进 RenderNode.reuse_key。

#### 2.3.2 blob v9 加一列
`loomgui_ffi_c/src/blob.rs`：VERSION 8→9，加第 22 列 `reuse_key: u32`。其他列结构不变。

#### 2.3.3 三个 FFI 口子（列表必需，也是通用能力）
1. `loomgui_stage_set_content_size(node, w, h)`——driver 注入滚动容器 content_size。核心 ScrollPane 用它而非子节点 AABB。`refresh_content_sizes` 跳过"已注入 content_size"的容器（ScrollPaneState 加 `content_size_overridden: bool` 标记，set_content_size 时置 true，refresh 跳过）。**清除 override**：driver 传特殊值（如 w=h=f32::NAN）或单独 `clear_content_size_override(node)` FFI 置 false，让核心重回子节点 AABB 自动模式。列表销毁/退回普通滚动时用。
2. `loomgui_stage_node_layout_rect(node, out_x, out_y, out_w, out_h)`——driver 读节点 layout_rect（solve 产物）。用于 itemSize 测量。
3. `loomgui_stage_get_scroll_pos(node, out_x, out_y)`——driver 读 scroll_pos。用于算可见区间。

**FFI 安全**：入口绝不 panic（坑 102），node 无效/非滚动容器 → out 填 0 早返，不 expect。

#### 2.3.4 refresh_content_sizes 改动
`loomgui_core/src/scroll.rs:465` `refresh_content_sizes`：遍历滚动容器时，若 `content_size_overridden` → 跳过子节点 AABB 计算，保留 driver 注入值。未注入的容器照旧算子节点 AABB（v1 普通滚动不受影响）。

### 2.4 后端改动

#### 2.4.1 MirrorPool keying
`loomgui_unity/Assets/LoomGUI/Runtime/MirrorPool.cs:38`：`Dictionary<uint, RenderObj>` 的 key 从 `node_id` 改为**复用键** `reuse_key != 0 ? reuse_key : node_id`。
- slot 换内容（NodeId 变、reuse_key 不变）→ 后端查复用键命中 → 复用 GO，只按 ChangeLevel 重建 mesh。
- 普通节点（reuse_key=0）→ 复用键 = node_id，行为不变。

**双 Dictionary 方案**（避免 key 空间冲突）：reuse_key>0 的 slot 节点和 reuse_key=0 的普通节点 key 空间不重叠（slot_id+1 ≥ 1，普通节点 node_id 是代际句柄高位含 gen），但为清晰起见用两个 dict：
- `_poolByNodeId: Dictionary<uint, RenderObj>`（reuse_key=0 的普通节点）
- `_poolByReuse: Dictionary<uint, RenderObj>`（reuse_key>0 的 slot 节点）

Sync 时按复用键查对应 dict。stale-mark-sweep 各自独立：本帧出现的复用键清 stale，未出现的销毁。slot 换绑（旧 NodeId 消失、新 NodeId 同 reuse_key）→ 同一复用键仍命中 → 不销毁。

**时序约束**（driver 侧保证）：一个 reuse_key 同一时刻只绑一个 NodeId。slot 换绑时 driver **先 remove_node 旧子树，再 instantiate 新子树设同 reuse_key**——避免新旧同 reuse_key 并存撞 dict。remove_node 后下帧 blob 不含旧 NodeId，但 reuse_key 已被新 NodeId 占用 → dict 命中新 NodeId，旧的自然被覆盖。

#### 2.4.2 FrameBlob.cs 加列
`loomgui_unity/Assets/LoomGUI/Runtime/FrameBlob.cs`：ExpectedVersion 8→9，加第 22 列 reuse_key reader，arena offset `21*4`→`22*4`。

### 2.5 driver 数据流（形态乙：宿主轮询，无 Rust→C# 回调）

**单向数据流**：driver 拉（query）核心状态，driver 推（set）数据进核心。无 Rust→C# 回调，IL2CPP 友好。

#### 2.5.1 列表初始化
1. driver `instantiate(pkg, "list_container")` 建列表容器（普通 div，`overflow:scroll; position:relative`——relative 作 absolute slot 的包含块）。
2. driver `instantiate(pkg, "item_template")` 建一个临时 item 测 itemSize。
3. **等一帧**（tick 跑 solve）。
4. `get_node_layout_rect(item)` 读尺寸 → itemSize（等高）/ 默认 size（不等高初始估算）。
5. `set_content_size(list_container, 0, total_content_h)` 注入总尺寸。
6. `remove_node(item_template)`（测量用完摘除）。

#### 2.5.2 每帧/滚动后
1. `get_scroll_pos(list_container)` 读 scroll_y。
2. **算可见区间**（见 2.6）→ 可见 slot 集合 `[(slot_id, item_index), ...]`。
3. **diff 上帧绑定**：
   - 新进入的 slot → `instantiate` item 子树 + `append_child(list_container)` + `set_reuse_key(new_node, slot_id)` + 设 `position:absolute; top:real_y; ...`。
   - 离开的 slot → `remove_node`（NodeId 变，但 reuse_key 已释放给新进入的 slot 复用 GO）。
   - 绑定的 item_index 变了 → `set_text/set_src/set_style` 改内容。
4. 核心 tick 照常：solve → build_render_nodes（slot 带 reuse_key 进 blob）→ 后端按 reuse_key 复用 GO。

#### 2.5.3 数据回填
driver 拉到可见 slot 绑定后，自己用 set_text/set_src 填数据（业务逻辑）。无回调。

### 2.6 可见区间算法（driver 侧）

#### 2.6.1 等高
```
first = floor(scroll_y / item_size)
last  = floor((scroll_y + viewport_h) / item_size)
```
O(1)。

#### 2.6.2 不等高
从 scroll_y 累加 `item_sizes` 找首个 `pos > scroll_y` 的 item。增量搜索（记录上次 first，向前/向后小步走，照 fgui GList.cs:1729-1763）。O(可见数)。

driver 维护 `item_sizes: Vec<f32>`（每 item index 的尺寸缓存）。

### 2.7 slot 定位（P1：absolute）

slot 用 `position:absolute` 定位到真实 item 位置：
```css
.slot { position:absolute; left:0; width:100%; height:item_h; top:real_y; }
```
- `real_y`：等高 `= item_index × item_size`；不等高 `= sum(item_sizes[0..item_index])`。
- `height`（item_h）：等高 `= item_size`（常量）；不等高 `= item_sizes[item_index]`（随绑定 item 变，driver 换绑时 `set_style` 设 height）。
- 滚动时 slot 的 top 不变（相对容器），scroll_pos 进容器 world matrix 平移整体（现有 ScrollPane 机制）。

列表容器 `position:relative`（absolute 的包含块）。

**为何不用 flex 流**：虚拟列表只有可视 slot 存在，flex 流会把它们从 y=0 开始排，而不是从 item_index 对应的真实位置。absolute 让 slot 精确定位到真实 y。

**为何不用 transform**：P1（absolute）语义更直观，且 absolute 围栏本期就做，两项协同。transform 也可行（不依赖 absolute）但语义绕。

### 2.8 不等高：尺寸补偿机制

不等高 item 首次渲染前 size 未知。解法（照 fgui GList.cs:1661-1707 + 2038-2043 + 2085）：

1. **初始估算**：用默认 size（item 模板首测值）填满 `item_sizes`，content_size = `item_count × default_size`。
2. **实测修正**：item 渲染后 `get_node_layout_rect` 读真实 size，若与缓存不同 → 更新 `item_sizes[index]` + 重算 content_size + `set_content_size`。
3. **防滚动跳动**：若该 item 在当前 scroll_pos **上方**（item 的 real_y < scroll_y），content_size 缩水会让 scroll_pos 相对位置变 → `set_scroll_pos` 同步偏移 delta，保持视口内容不动。item 在视口内/下方变 size → 只更新 content_size，不调 scroll_pos。

**纯 driver 侧，零核心改**：driver 读旧 content_size + 算 delta + `set_content_size` 新值 + 必要时 `set_scroll_pos` 修正。核心只提供 set_content_size/set_scroll_pos（已有 + 本期新增），不需 `adjust_content_size_on_scroll` 原语。

### 2.9 不等高时序与边界

- **首帧估算→次帧修正循环**：driver 填数据后要等一帧 solve 才能读实测 size，但可见区间要 size 才能算。照 fgui HandleScroll1 的"填不满重试 20 次"（GList.cs:1884-1895）防死循环：driver 设最大重试次数，超时用估算值兜底。
- **首帧列表尺寸不对**：itemSize 未测出前 content_size=0，首帧不可滚。第二帧起正确。可接受（列表初始化一次性代价）。

### 2.10 等高 vs 不等高对比

| | 等高 | 不等高 |
|---|---|---|
| item_sizes | 全同（一个值） | Vec<f32>，每 item 不同 |
| content_size | count × size | sum(item_sizes) |
| 可见区间 | O(1) floor | O(可见数) 累加搜索 |
| slot top | index × size | sum(item_sizes[0..index]) |
| 尺寸补偿 | 不需要 | 需要（实测 size 变 → 修 content_size + scroll_pos） |
| 核心/FFI/blob | 不变 | 不变（全 driver 侧） |

**不等高是等高的平滑扩展**：核心/FFI/blob/reuse_key 机制完全不变，只是 driver 算法从"乘"换"累加 + 尺寸补偿"。选层 B' 的正确性验证。

## 3. 不做什么

- **`<l-list>` 标签**：围栏只有 div/span/img/button，列表是普通 div + slot，AI 不会写专用标签（硬约束，main-design §3.1）。
- **NodeKind::List**：核心不认识列表（层 B'），无 NodeKind 枚举改动，不碰包格式。
- **itemRenderer 回调**：形态乙（宿主轮询）无 Rust→C# 回调，IL2CPP 友好。
- **soft clip（羽化）**：推 v2，和 shape mask/paintingMode 一起。
- **不同模板 item**：本期同模板（slot 子树结构固定，不同 item 只改叶子内容 set_text/set_src/set_style）。不同模板（itemProvider 式）推后——但层 B' 的 reuse_key 机制天然支持（slot 换绑时 instantiate 不同模板，reuse_key 不变 GO 仍复用），未来扩展不推翻。
- **loop 列表**（fgui 6 倍量无缝循环）：推后。
